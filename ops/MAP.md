# Карта Кампуса для агрегатора правок

Оглавление, а не пересказ. Агрегатор читает этот файл и реестр, остальное подгружает по ссылкам
под задачу. Пути от корня `campus-infra`.

## Системы и репозитории

| Система | Основная копия | Документация | Стек |
|---|---|---|---|
| АСПиРС | `aspirs/` | `aspirs/docs/`, `aspirs/CLAUDE.md` | FastAPI, Postgres, Next |
| Кампус.ЛКП | `klkp/` | `klkp/docs/` | FastAPI, Postgres, PWA |
| Кампус.Шлюз | `aspirs-klpk-gateway/` | `aspirs-klpk-gateway/deploy/SETUP.md` | FastAPI, mTLS |
| Контракты | `campus-contracts/` | `campus-contracts/docs/CONTRACT.md` | pydantic |
| Кампус.Выезд | `sirius-eviction/` | `sirius-eviction/CLAUDE.md` | |

Сквозное: `docs/ARCHITECTURE.md` (кто где стоит и с кем говорит), `docs/EXCHANGE.md` (конверт,
типы, грабли обмена), `docs/OVERVIEW.md` (что умеют системы), `docs/BACKLOG.md` (открытые
вопросы), `deploy-onevps/00-README.md` (выкладка одной машины).

## Рабочие копии

Параллельные ветки живут в соседних worktree с суффиксом: `aspirs-posts`, `klkp-posts`,
`campus-contracts-posts`, `aspirs-klpk-gateway-posts`, `aspirs-changes`, `aspirs-journal`,
`aspirs-levels`. Новая задача получает свой worktree от main:
`git -C <репо> worktree add ../<репо>-<коротко> -b <ветка> main`.
Основную копию на main под задачу не занимаем, там могут быть чужие правки.

## Зависимости

```
campus-contracts ──пин по коммиту тега──▶ aspirs-klpk-gateway, klkp, aspirs
klkp ◀──mTLS──▶ aspirs-klpk-gateway ──▶ aspirs /integration/*
```

Новый тип или поле в обмене: версия контрактов, тег, пин во всех трёх, белый список шлюза.
Старый шлюз отвергает незнакомые типы, поэтому порядок выкладки: контракты, шлюз, КЛКП, АСПиРС.

## Выкладка

Пуш main в АСПиРС, КЛКП или Выезд запускает выкладку. Шлюз выкладывается руками.
Исполнители не пушат и не выкладывают, это делает пользователь или агрегатор по прямому
разрешению. Подробности выкладки, адреса и учётки в памяти сессии, не здесь.

## Где правки теряются

- незакоммиченное в основной копии, куда пишут несколько сессий;
- ветка в worktree, которую не слили в main;
- main, который не запушен, потому что пуш означает выкладку;
- контракт с новой версией без тега или без пина в одной из систем;
- пересборка ветки от main, после которой старые коммиты висят в `*-old`.

Всё это ловит `ops/campus_status.py`.
